# 出発前夜（dungeon-prep）

探索前の準備で勝負が決まる、ブラウザで遊べるローグライク・ダンジョン探索ゲーム。

## 遊び方

0. **ダンジョンを選ぶ**：挑戦を始めるたびに、どのダンジョンに挑むかを選ぶ（ダンジョンごとに、階の数・広さ・満腹度・出る敵などが違う。管理画面で作れる）。
1. **出発**：ダンジョンの特性（炎・氷・無属性・光・闇のどれか）は挑むたびに変わる。持ち物は、その特性に有利な装備と回復薬2つ、そのダンジョンで有利に働く呪文書2冊（`src/game/depart.ts`）。
2. **ダンジョン**：毎回形の変わる3Dの迷宮を、霧の中で探索する。1歩ごとに満腹度が減る。敵はマップ上を動き、体当たりで戦う。防具は敵の属性に、武器は敵の体質（柔らかい・硬い・霊体）に合わせると効く。脇道の宝箱には金貨や道具が入っている。最後の階の下のボス階でボスを倒せば踏破。
3. **結果**：ダンジョンの正体と、倒した敵・持ち帰った金貨が出て、次の挑戦へ。
4. **記録**：何回目の挑戦かは、ブラウザに自動で保存される。探索の途中で閉じても、続きから遊べる。難しさの段階は、広さや満腹度を変えたダンジョンを増やして表す（管理画面で作る）。

ダンジョンは Three.js で、斜め上から見下ろす3Dで描いている。スマホのブラウザでも、マスをタップするか画面を指でなぞって歩ける。

設計の決定事項と未決事項は [docs/dungeon-design.md](docs/dungeon-design.md) にまとめている。

## 技術構成

- React + TypeScript + Vite
- Three.js（ダンジョンの3D表示）
- ゲームロジックは `src/game/` の純粋なTypeScriptで、UIから分離
- テストは Vitest

```

  game/     ルール（状態を受け取り新しい状態を返す純粋関数）
    depart.ts      出発：特性を決め、店で選んだ持ち物を持たせる
    shop.ts        出発の準備（店）：買う・持っていくものを選ぶ・持ち帰った金貨と道具を戻す
    itemMaster.ts  品物の設定（items.json）を読んで確かめる。武器・防具の10段階
    items.json     品物の名前・値段と、武器・防具の段階ごとの性能（管理画面の「品物」タブで直す）
    map.ts         階層マップの生成（小部屋＋迷路、階段、宝箱・強敵の配置、ボス階）

    exploreTypes.ts 探索の状態・行動・出来事の型と、探索の数値
    exploreSight.ts 視界の計算（見えるマス・見通し・向き）
    magic.ts       魔法の計算（魔力・魔法の強さ・呪文のダメージ・属性の相性）
    enemies.ts     マップ上の敵：配置・追跡の経路・うろつき

    explore3d.ts       3D表示の本体（数値は explore3dConfig、床・壁の貼り方と霧は explore3dKit）
```

## 設計のポイント

- **ロジックとUIの分離**：ルールはすべて `src/game/` にあり、React に依存しない。
- **シード付き乱数**：乱数の状態も state に持たせ、同じシードなら必ず同じ結果になる。テストやバグ再現がしやすい。
- **判別可能なユニオン型**：アイテムの効果や戦闘の行動を型で表し、処理の書き漏れを型チェックで検出する。
- **Result 型**：不正な操作は例外ではなく値でエラーを返し、画面でそのまま表示する。
- **答えを画面に渡さない**：`toPlayerView` で正解の特性を取り除いた状態だけを UI に渡す。
- **ドット絵をデータで持つ**：1行32文字の文字列で絵を表し、SVGやCanvasで描画する。主人公のマントは装備した防具の色に差し替わるので、準備が当たったかが見た目でもわかる。画像ファイルがいらず、変更点もGitの差分で読める。
- **バランスをテストで守る**：プレイヤーと同じ情報だけで動く自動プレイAIに多数回遊ばせ、「正しい準備ならクリア率80%以上、外れれば20%未満」をテストしている。数値を調整してもコンセプトが崩れない。

## 開発

```bash
npm install
npm run dev     # 開発サーバー
npm test        # テスト（バランスのテストは時間がかかるので、今は外している）
npm run test:balance  # バランスのテスト（自動プレイで標準のダンジョンを何百回も遊ばせる）
npm run build   # 型チェック＋ビルド
```

開発用の確認画面：`?view=admin`（敵のマスターデータ・品物の設定・ダンジョンの設定の管理画面。変えて公開もできる。`docs/enemy-master.md`）、`?view=map`（マップ生成）、`?view=explore`（探索だけを試す。`&seed=1` で階層、`&trait=fire` で特性、`&best=1` でダンジョンに合わせたいちばん強い装備・道具・呪文書を指定。画面上の「いちばん強い装備で試す」でも切り替えられる）
