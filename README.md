# 出発前夜（dungeon-prep）

探索前の準備で勝負が決まる、ブラウザで遊べるローグライク・ダンジョン探索ゲーム。

## 遊び方

1. **準備フェーズ（3日間）**：配られた5枚の手札から、1日1枚カードを使う。酒場の噂や情報屋でダンジョンの特性（炎・氷・無属性・光・闇のどれか）を探り、地図を買い、鍛冶屋と道具屋で装備と道具をそろえる。
2. **出発の朝**：余ったカードを最大3枚、次の挑戦に持ち越せる。持ち越した分だけ、次に新しく引ける枚数は減る。
3. **ダンジョン**：毎回形の変わる3Dの迷宮を、霧の中で探索する。1歩ごとに満腹度が減る。敵はマップ上を動き、体当たりで戦う。防具は敵の属性に、武器は敵の体質（柔らかい・硬い・霊体）に合わせると効く。脇道の宝箱には金貨や道具が入っている。3階の下のボス階でボスを倒せば踏破。
4. **結果**：ダンジョンの正体が明かされ、次の挑戦へ。持ち帰った金貨は次の準備の所持金に足される（力尽きたら半分）。
5. **ランク**：踏破すると経験が手に入る。準備フェーズで経験と金貨を払うとランクが上がり、ダンジョンが広くなるかわりに満腹度の上限と報酬が増える。進み具合はブラウザに自動で保存される。

ダンジョンは Three.js で、斜め上から見下ろす3Dで描いている。スマホのブラウザでも、マスをタップするか画面を指でなぞって歩ける。

設計の決定事項と未決事項は [docs/dungeon-design.md](docs/dungeon-design.md) にまとめている。

## 技術構成

- React + TypeScript + Vite
- Three.js（ダンジョンの3D表示）
- ゲームロジックは `src/game/` の純粋なTypeScriptで、UIから分離
- テストは Vitest

```
src/
  game/     ルール（状態を受け取り新しい状態を返す純粋関数）
    prep.ts        準備フェーズ：カード使用・買い物・持ち越し
    map.ts         階層マップの生成（小部屋＋迷路、階段、宝箱・強敵の配置、ボス階）
    explore.ts     探索の進行：移動・霧・満腹度・道具・宝箱・敵の手番・戦闘・ボス
    enemies.ts     マップ上の敵：配置・追跡の経路・うろつき
    combat.ts      ダメージ計算：武器と体質、防具と属性、属性付与
    autoplay.ts    自動プレイAI（バランステスト用）
    rank.ts        ランク（強化）：広さ・満腹度・敵の数・報酬
    save.ts        セーブデータの形と読み込み
    runSave.ts     探索の途中の状態の保存と読み込み（中断と再開）
    rng.ts         シード付き乱数
    data.ts        カード・アイテム・敵・相性表・設定値
  ui/       画面（ロジックを呼び出して表示するだけ）
  sprites/  32×32のドット絵（文字列データ）と、SVG・Canvasで描く部品
scripts/
  sprite-shapes.ts  ドット絵の形を図形の組み合わせで定義
  build-sprites.ts  src/sprites/data.ts を生成する
  build-tiles.ts    2D表示の仮のタイル素材（public/tiles/*.png）を生成する（仕様は docs/tiles.md）
  build-textures.ts 3D表示の仮のテクスチャ（public/textures/{特性}/*.png、128px・なめらかな質感）を生成する（仕様は docs/textures.md）
  build-photo-textures.py 端でつながる画像1枚（assets/texture-sources/）から、3D表示のテクスチャ3枚（床・壁の上面・壁の側面）を作る（Python・Pillow）
  build-chest-textures.py 宝箱の写真（assets/texture-sources/chest.jpg）から、宝箱のテクスチャ3枚（正面・横・ふた）を作る（Python・Pillow）
  pixels.ts         素材を作るスクリプトの共通部品（色・PNGの書き出し）
```

## 設計のポイント

- **ロジックとUIの分離**：ルールはすべて `src/game/` にあり、React に依存しない。
- **シード付き乱数**：乱数の状態も state に持たせ、同じシードなら必ず同じ結果になる。テストやバグ再現がしやすい。
- **判別可能なユニオン型**：カード効果や戦闘の行動を型で表し、処理の書き漏れを型チェックで検出する。
- **Result 型**：不正な操作は例外ではなく値でエラーを返し、画面でそのまま表示する。
- **答えを画面に渡さない**：`toPlayerView` で正解の特性を取り除いた状態だけを UI に渡す。
- **ドット絵をデータで持つ**：1行32文字の文字列で絵を表し、SVGやCanvasで描画する。主人公のマントは装備した防具の色に差し替わるので、準備が当たったかが見た目でもわかる。画像ファイルがいらず、変更点もGitの差分で読める。
- **バランスをテストで守る**：プレイヤーと同じ情報だけで動く自動プレイAIに多数回遊ばせ、「正しい準備ならクリア率80%以上、外れれば20%未満」をテストしている。数値を調整してもコンセプトが崩れない。

## 開発

```bash
npm install
npm run dev     # 開発サーバー
npm test        # テスト
npm run build   # 型チェック＋ビルド
```

開発用の確認画面：`?view=map`（マップ生成）、`?view=explore`（探索だけを試す。`&seed=1` で階層、`&rank=3` で広さ、`&trait=fire` で特性、`&render=2d` で2D表示、`&best=1` でダンジョンに合わせたいちばん強い装備・道具・呪文書を指定。画面上の「いちばん強い装備で試す」でも切り替えられる）
