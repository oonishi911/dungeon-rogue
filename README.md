# 出発前夜（dungeon-prep）

探索前の準備で勝負が決まる、ブラウザで遊べるローグライク・ダンジョン探索ゲーム。

## 遊び方

1. **準備フェーズ（3日間）**：配られた5枚の手札から、1日1枚カードを使う。酒場の噂や情報屋でダンジョンの特性（炎か毒か）を探り、店で対策の装備をそろえる。
2. **出発の朝**：余ったカードを最大3枚、次の挑戦に持ち越せる。持ち越した分だけ、次に新しく引ける枚数は減る。
3. **ダンジョン**：3フロア＋ボスをターン制で戦う。特性に合ったマントを着ていればダメージを大きく減らせる。
4. **結果**：ダンジョンの正体が明かされ、次の挑戦へ。

## 技術構成

- React + TypeScript + Vite
- ゲームロジックは `src/game/` の純粋なTypeScriptで、UIから分離
- テストは Vitest

```
src/
  game/     ルール（状態を受け取り新しい状態を返す純粋関数）
    prep.ts        準備フェーズ：カード使用・買い物・持ち越し
    combat.ts      ターン制戦闘：ダメージ計算・耐性・毒
    expedition.ts  探索の進行（手動プレイと自動プレイで共通）
    rng.ts         シード付き乱数
    data.ts        カード・アイテム・敵・設定値
  ui/       画面（ロジックを呼び出して表示するだけ）
  sprites/  32×32のドット絵（文字列データ）とSVGで描く部品
scripts/
  sprite-shapes.ts  ドット絵の形を図形の組み合わせで定義
  build-sprites.ts  src/sprites/data.ts を生成する
```

## 設計のポイント

- **ロジックとUIの分離**：ルールはすべて `src/game/` にあり、React に依存しない。
- **シード付き乱数**：乱数の状態も state に持たせ、同じシードなら必ず同じ結果になる。テストやバグ再現がしやすい。
- **判別可能なユニオン型**：カード効果や戦闘の行動を型で表し、処理の書き漏れを型チェックで検出する。
- **Result 型**：不正な操作は例外ではなく値でエラーを返し、画面でそのまま表示する。
- **答えを画面に渡さない**：`toPlayerView` で正解の特性を取り除いた状態だけを UI に渡す。
- **ドット絵をデータで持つ**：1行32文字の文字列で絵を表し、SVGで描画する。主人公のマントは装備した防具の色に差し替わるので、準備が当たったかが見た目でもわかる。画像ファイルがいらず、変更点もGitの差分で読める。
- **バランスをテストで守る**：自動プレイで多数回シミュレーションし、「正しい準備ならクリア率80%以上、外れれば20%未満」をテストしている。数値を調整してもコンセプトが崩れない。

## 開発

```bash
npm install
npm run dev     # 開発サーバー
npm test        # テスト
npm run build   # 型チェック＋ビルド
```
