# 敵のマスターデータと管理画面

敵の名前・強さ・属性・体質・ボスかどうか・見た目（もとのドット絵と色の差し替え）、ダンジョンごとに出る敵（道中の出やすさとボス）は、
`src/game/enemies.json` にある。プログラムは起動時にこれを読み、正しい形かを確かめる（`src/game/enemyMaster.ts`）。
敵の種類はプログラムに決め打ちしていない。`enemies.json` にある敵がすべてで、管理画面から足す・消すことができる。

## 管理画面（`?view=enemies`）

公開版や `npm run dev` のURLの後ろに `?view=enemies` を付けて開く。プレイヤーの画面からは行けない。

- **敵**：名前・HP・攻撃・防御・属性・体質・ボス・見た目を変えられる。ボス以外の敵は、ゲームの中ではHPと攻撃が `ENEMY_CONFIG.strengthRate` 倍になる（表の「ゲーム内」の数字）。見た目は、今いる敵の見た目から選ぶ
- **倒したときの報酬**：敵ごとの金貨・経験値・道具を落とす確率（%）。強敵は金貨と経験値が3倍になり、必ず宝箱を落とす。ボスは使わない（ボスの報酬はランクで決まる）
- **敵を足す**：ID（英小文字で始まり、英小文字・数字・_ だけ）と名前を決め、「見た目と強さのもと」にした敵の値を写して足す。足した敵は、ダンジョンの出やすさを決めるまで、どのダンジョンにも出ない
- **敵を消す**：「消す」を押すと、その敵はどのダンジョンにも出なくなる。ボスにしているダンジョンがある敵は、先にボスを変えないと消せない
- **ダンジョンに出る敵**：道中の出やすさ（0〜9。0は出ない）と、ボス（ボスにした敵から選ぶ）
- 公開版から変えたところは、枠が金色になる。変えた内容は「変更を公開」の上に一覧で出る
- 入力した値は、その場で確かめる（敵の管理画面・ダンジョンの設定の両方）。決まりに合わなければ、欄の枠が赤くなり、欄の下に原因と正しい値を出す（例：「15 は大きすぎます。1〜12の整数を入れてください。」「最小（11）が、最大（10）より大きくなっています。10以下にしてください。」）。言葉は `src/game/fieldCheck.ts` で作る。直すまで公開はできない
- 難しさの検査（バランステスト）は、その場では確かめない（自動プレイを何百回も回すので時間がかかる）。公開したあとの自動チェックで確かめる
- おかしい値（名前が空・ほかの敵と同じ名前、ボスでない敵をボスに選んだ、道中に敵が1体もいない、など）があると、公開できない

### 変更を公開する

1. GitHub のトークンを作り、画面の欄に貼る（作り方は画面の「トークンの作り方」）。このリポジトリだけ・Contents の読み書きと Actions の読み取りだけを許した、期限つきのトークンにする
2. 「変更を公開」を押すと、`src/game/enemies.json` が main に直接保存される（コミットの説明に、変えた内容が並ぶ）
3. 保存すると CI が動く。自動チェック（型・テスト・ビルド）が通れば公開され、画面に「公開しました」と出る。ゲームを読み込み直すと新しいデータになる
4. 自動チェックが通らなかったときは公開されない。強さを大きく変えると、バランスのテスト（`balance.test.ts`）の基準を外れて止まることがある

- トークンは、「このブラウザに覚えておく」を選んだときだけ、そのブラウザに保存する（ほかには送らない。GitHub を除く）
- 画面を開いたあとに、ほかの変更が先に `enemies.json` に入っていたときは、上書きしないで止める。公開が終わるのを待って、画面を読み込み直してから変更する
- 道中の出やすさを変えるときは、ほかの敵の並び順を変えない（並び順も乱数の結果に関わるため）

## 敵の立体の模型

- 敵は、形も色もプログラムで組んだ立体の模型で描く（`src/ui/creatures.ts`、`docs/textures.md`）。模型は管理画面では足せない
- 模型のない敵（管理画面で足した敵など）は、データの見た目（ドット絵）で描く

## テスト

- テストは特定の敵（ゴブリンなど）に頼らない。敵を使うテストは、データにある敵から選ぶ（`src/game/enemies.fixtures.ts`）。管理画面で敵を消しても、テストは通る
- `enemyMaster.ts` の関数は、決まった中身のデータ（`src/game/enemyMaster.sample.json`）で確かめる
