# 敵のマスターデータ・ダンジョンの設定ファイルと管理画面

敵の名前・強さ・属性・体質・ボスかどうか・見た目（もとのドット絵と色の差し替え）・倒したときの報酬は、
`src/game/enemies.json`（敵のマスター）にある。プログラムは起動時にこれを読み、正しい形かを確かめる（`src/game/enemyMaster.ts`）。
敵の種類はプログラムに決め打ちしていない。`enemies.json` にある敵がすべてで、管理画面から足す・消すことができる。

どのダンジョンにどの敵が出るか（道中の出やすさとボス）は、マスターには書かない。ダンジョンの設定ファイル
（`src/game/dungeons/<ID>.json` の `encounters`。`docs/dungeon-design.md`）に、ダンジョンの属性ごとに、マスターの敵から選んで書く。

## ダンジョンの設定ファイル（プレイヤーが選ぶダンジョン）

- `src/game/dungeons/` にある設定ファイル1つが、プレイヤーの選べるダンジョン1つ。ファイルの名前（拡張子なし）がダンジョンの ID
- プレイヤーは、挑戦を始めるたびに、ダンジョンを選ぶ画面（`src/ui/DungeonSelectScreen.tsx`）で、どのダンジョンに挑むかを選ぶ。画面には、名前・説明と、階の数・広さ・満腹度が出る
- ファイルを置くだけで、選ぶ画面に並ぶ（プログラムに一覧を書く必要はない。`src/game/dungeons.ts` が、フォルダのファイルをすべて読み込む）。並び順は、標準のダンジョンが先頭で、あとは ID の順
- 標準のダンジョン（`standard.json`）は消せない。ダンジョンを指定しないとき（開発用の画面など）と、ダンジョンを選べるようになる前の途中保存は、標準のダンジョンを使う
- 1つのファイルに入っているもの：名前・説明（`name`・`description`）、マップと探索の設定（`floors`・`rooms`・`enemies`・`growth`・`magic`・`spells`）、属性ごとに出る敵（`encounters`）
- 探索の途中保存には、遊んでいるダンジョンの ID を残す。そのダンジョンのファイルが消されていたら、続きからは遊べない（新しい挑戦になる）

## 管理画面（`?view=admin`）

公開版や `npm run dev` のURLの後ろに `?view=admin` を付けて開く。プレイヤーの画面からは行けない。

管理画面は、敵のマスターデータ（`enemies.json`）とダンジョンの設定ファイル（`src/game/dungeons/<ID>.json`。`docs/dungeon-design.md`）を1つにまとめた画面で、種類ごとのタブに分かれている。
ダンジョンの設定のタブでは、タブの下の「直すダンジョン」の欄で、どのダンジョンを直すかを選ぶ（新しく作るダンジョンには「（新しく作る）」、変えたダンジョンには「（変更あり）」と出る）。

| タブ | 変えるもの | 保存先 |
|---|---|---|
| 敵 | 敵の値・敵を足す／消す（すべてのダンジョンで使う、敵のマスター） | `enemies.json` |
| 名前と説明 | 選ぶ画面に出す名前と説明、ダンジョンを複製して作る／消す | 選んだダンジョンのファイル |
| ダンジョンに出る敵 | 属性ごとの道中の出やすさとボス（マスターの敵から選ぶ） | 選んだダンジョンのファイル |
| 階の数・広さ・満腹度／小部屋／敵の数と置き方／レベルと強敵の報酬／魔法 | マップと探索の設定 | 選んだダンジョンのファイル |

`?view=admin&tab=pool&dungeon=deep_cave` のように、住所の `tab=`（`enemies`・`about`・`pool`・`floors`・`rooms`・`placement`・`growth`・`magic`）でタブを、`dungeon=` で直すダンジョンを指して開ける（`dungeon=` がなければ標準のダンジョン）。前の住所の `?view=enemies`（「敵」を開く）と `?view=gen`（「階の数・広さ・満腹度」を開く。`&tab=` も使える）も、今までどおり開ける。値を変えたタブには、点が付く（ダンジョンの設定のタブは、直しているダンジョンの分）。

- **敵**：名前・HP・攻撃・防御・属性・体質・ボス・見た目を変えられる。ボス以外の敵は、ゲームの中ではHPと攻撃が `ENEMY_CONFIG.strengthRate` 倍になる（表の「ゲーム内」の数字）。見た目は、今いる敵の見た目から選ぶ
- **倒したときの報酬**：敵ごとの金貨・経験値・道具を落とす確率（%）。強敵は金貨と経験値がダンジョンごとの倍率（「レベルと強敵の報酬」タブ）で増え、必ず宝箱を落とす。ボスは使わない（ボスの報酬は、ボスを倒したときに一定の金貨が出る。`TREASURE_CONFIG.bossGold`）
- **敵を足す**：ID（英小文字で始まり、英小文字・数字・_ だけ）と名前を決め、「見た目と強さのもと」にした敵の値を写して足す。足した敵は、ダンジョンごとの出やすさを決めるまで、どのダンジョンにも出ない
- **敵を消す**：「消す」を押すと、マスターから消え、すべてのダンジョンの道中からも外れる。どれかのダンジョンでボスにしている敵は、先にボスを変えないと消せない（ボタンに、どのダンジョンのどの属性のボスかが出る）
- **ダンジョンに出る敵**（「ダンジョンに出る敵」タブ）：選んだダンジョンの、属性ごとの道中の出やすさ（0〜9。0は出ない）と、ボス（ボスにした敵から選ぶ）
- **ダンジョンを作る**（「名前と説明」タブ）：今選んでいるダンジョンを複製して作る。ID（英小文字で始まり、英小文字・数字・_ だけ。ファイルの名前になる）と名前を決める。作ったダンジョンは、すぐに「直すダンジョン」に選ばれる
- **ダンジョンを消す**（「名前と説明」タブ）：公開すると、そのファイルが消え、プレイヤーは選べなくなる。標準のダンジョンは消せない
- 公開版から変えたところは、枠が金色になる。変えた内容は「変更を公開」の上に一覧で出る
- 入力した値は、その場で確かめる（どのタブでも）。決まりに合わなければ、欄の枠が赤くなり、欄の下に原因と正しい値を出す（例：「15 は大きすぎます。1〜12の整数を入れてください。」「最小（11）が、最大（10）より大きくなっています。10以下にしてください。」）。言葉は `src/game/fieldCheck.ts` で作る。直すまで公開はできない
- 難しさの検査（バランステスト）は、今は自動チェックから外している（ダンジョンの設定を自由に試せるように）。確かめるときは、手元で `npm run test:balance` を動かす（標準のダンジョンを確かめる）
- おかしい値（名前が空・ほかの敵やダンジョンと同じ名前、ボスでない敵をボスに選んだ、道中に敵が1体もいない、など）があると、公開できない。どのダンジョンのことかは、頭に名前が付く

### 変更を公開する

1. GitHub のトークンを作り、画面の欄に貼る（作り方は画面の「トークンの作り方」）。このリポジトリだけ・Contents の読み書きと Actions の読み取りだけを許した、期限つきのトークンにする
2. 「変更を公開」を押すと、変えたファイル（敵を変えたら `src/game/enemies.json`、ダンジョンを変えたらそのダンジョンのファイル。作ったダンジョンはファイルを作り、消したダンジョンはファイルを消す）が、**1回のコミットで**まとめて main に直接保存される（コミットの説明に、変えた内容が並ぶ。保存するファイルは、画面の「変更を公開」の欄にも出る）。タブやダンジョンをまたいで変えても、1回の公開で済み、自動チェックも1回だけ動く。途中までしか保存されない、ということはない
3. 保存すると CI が動く。自動チェック（型・テスト・ビルド）が通れば公開され、画面に「公開しました」と出る。ゲームを読み込み直すと新しいデータになる
4. 自動チェックが通らなかったときは公開されない（ファイルの形がおかしいときなど）

- トークンは、「このブラウザに覚えておく」を選んだときだけ、そのブラウザに保存する（ほかには送らない。GitHub を除く）
- 画面を開いたあとに、保存するファイルのどれかに、ほかの変更が先に入っていたとき（作るはずのファイルがもうある、消すはずのファイルがもうない、も同じ）は、何も保存しないで止める（調べてから保存するまでのあいだに入ったときも、上書きしないで止まる）。公開が終わるのを待って、画面を読み込み直してから変更する
- 道中の出やすさを変えるときは、ほかの敵の並び順を変えない（並び順も乱数の結果に関わるため）

## 敵の立体の模型

- 敵は、形も色もプログラムで組んだ立体の模型で描く（`src/ui/creatures.ts`、`docs/textures.md`）。模型は管理画面では足せない
- 模型のない敵（管理画面で足した敵など）は、データの見た目（ドット絵）で描く

## テスト

- テストは特定の敵（ゴブリンなど）に頼らない。敵を使うテストは、データにある敵から選ぶ（`src/game/enemies.fixtures.ts`）。管理画面で敵を消しても、テストは通る
- `enemyMaster.ts` の関数は、決まった中身のデータ（`src/game/enemyMaster.sample.json`。敵のマスターと、属性ごとに出る敵の見本）で確かめる
- テストは、標準のダンジョン以外の設定ファイルに頼らない（管理画面でダンジョンを作ったり消したりしても、テストは通る）。ほかのダンジョンで遊ぶことを確かめるテストは、テストの中でだけ一覧に足すダンジョンを使う（`src/game/explore.test.ts`）
- どの設定ファイルも、形が正しいことと、書き出すと同じ中身になることを確かめる（`src/game/genMaster.test.ts`）
