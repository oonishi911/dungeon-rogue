# ダンジョン再設計

現状の「固定3フロア×敵2体＋ボス」の一本道を、見下ろし型の自動生成マップに作り替える。
ダンジョン特性の見直しは、この構成を前提に行う。

## 決定事項

### マップ
- マス目のマップを、斜め上から見下ろす3Dで表現する。
- 1階層の広さは可変（20×20〜100×100）。広さは、ダンジョンの設定（管理画面 `?view=admin` の「階の数・広さ・満腹度」タブ）で決める。
- 毎回ランダムに生成する。シード付き乱数を使い、同じシードなら同じマップになる。
- マスは **壁** と **通路** の2種類。道は一本道ではなく分岐する。
- 階段で下の階へ進める。上の階へは戻れない。
- 階層数は **3階＋ボス階**（今の設定）。通常の階の数は、ダンジョンの設定（管理画面 `?view=admin` の「階の数・広さ・満腹度」タブ）で変えられる（1〜10）。
- 階段へ続く道（本道）以外の脇道には、宝箱や強敵がランダムに置かれる。
- **霧あり**：まだ見ていない場所は表示されない。主人公から6マス以内は、壁の向こうや曲がり角の先も含めてすべて見える（主人公の視界は壁にさえぎられない）。敵の視界は今までどおり壁にさえぎられるので、壁の向こうの敵には先に気付ける。

### 敵
- 敵はマップ上に見える形で置く（シンボルエンカウント）。
- 通常の敵は、プレイヤーが1回行動するたびに移動する。
- **強敵とボスは移動しない**。
- 通常の敵は、ふだんはランダムにうろつき、プレイヤーが視界に入ると追ってくる。見失って数ターン経つと、うろつきに戻る。
- 移動の速さはプレイヤーと同じ（1行動で1マス）。

### 戦闘
- **マップ上でそのまま戦う**。隣のマスにいる敵の方向へ進むと攻撃になる（体当たり方式）。
- 攻撃・道具の使用・移動は、どれも1行動として数える。満腹度も1行動ごとに減る。
- **不意打ち**：まだプレイヤーに気付いていない敵（うろついている状態）を攻撃すると、ダメージが大きく増える。
- **背後からの攻撃**：隣にいる敵から離れると、一定の確率で背後から攻撃される。強敵とボスから離れるときは必ず攻撃される。
- **倒したときの報酬**（`REWARD_CONFIG`。敵ごとの値は `enemies.json` の `reward` で敵の管理画面、レベルの上がり方と強敵の倍率はダンジョンの設定ファイルの `growth` で、ダンジョンごとに管理画面から変えられる）：
  - 金貨：敵ごとの金貨（強敵は倍率つき）。その場で手に入る
  - 道具：敵ごとの確率（今は10%）で回復薬か食料を落とし、持ち物に入る。持ち物がいっぱいなら、その場に宝箱で残す
  - 経験値：たまるとレベルが上がる（この挑戦のあいだだけ。1レベルで最大HP+2・攻撃+1、上がった分だけHPも回復）。レベル1→2は30、そこから1レベルごとに20ずつ多く要る。上限はレベル10
  - 強敵：金貨と経験値が3倍。さらに必ず宝箱を落とし、金貨30Gと良い道具（回復薬・食料・砥石・聖水・闇の油のどれか）が入っている
  - レベルの上がり方は、自動プレイのバランステストを満たす範囲にしている（無属性のダンジョンの外れた準備のクリア率は、報酬なしの77.5%から87.5%になった。上限は90%）
- **複数の敵**：囲まれたときの特別なルールは作らない。通路で戦えば一度に1体ずつ相手にできる、という地形の戦術をそのまま活かす。

### 魔法
- **魔力と呪文書**：呪文書を持っていくと、その呪文を魔力を使って何度でも唱えられる。呪文書は道具の8枠とは別に、3冊まで（同じ呪文書は1冊）。呪文書を持っていなければ魔力もなく、魔力の棒も出ない
- **入手**：出発の準備（店）で買う。一度買えばずっと使え、出発のたびに3冊まで選んで持っていく
- **魔力**：探索を始めるときはいっぱい（20）。6行動ごとに1戻る。杖を持っていると、魔力の最大が10増え、魔法が1.5倍強くなる
- **呪文のダメージ**：魔法の強さ（8）×呪文の倍率。敵の防御は無視する。唱えると、3マス以内のうろついている敵が気付く。呪文で倒しても、ふつうに倒したときと同じ報酬が入る
- **呪文**（使う魔力・効き目。数値はすべて管理画面 `?view=admin` の「魔法」タブで変えられる）：
  - 衝撃波（6）：まわり8マスの敵を、主人公から離れる向きへ3マス吹き飛ばす。ダメージは控えめ（倍率0.3）。壁や別の敵にぶつかると、その手前で止まり、3の追加ダメージ。ボスは吹き飛ばない
  - なぎ払い（5）：向いた方向の3マスを貫き、並んだ敵すべてに当たる（倍率0.8）
  - 炎の矢・氷の矢・光の槍・闇の矢（4）：向いた方向へ6マスまで飛び、最初に当たった敵に属性のダメージ（倍率1。属性の相性は砥石・聖水と同じ）
  - 癒し（6）：HPを20回復する
  - 再生（5）：8ターンのあいだ、1ターンにHPを3回復する
- **操作**：呪文のボタン（キーボードは Z・X・C）。向きのある呪文（なぎ払い・矢）は、主人公が向いている方向（最後に歩こうとした向き。壁にぶつかって歩けなかったときも、その向きを向く）に唱える。向きを選ぶ矢印のボタンは出さない
- **演出と音**（`src/ui/spellFx.ts`。2026-11-14 に、派手に作り直した）：呪文ごとに効果音を鳴らす（`docs/sounds.md`）
  - どの呪文にも：唱えると足元に呪文の色の魔法陣が開き、光の柱が立つ。呪文の光が床と壁を照らす（影を作らない光を2つ使い回す）。強い呪文は画面を揺らし、一瞬光らせる（闇は暗くする）。動きを減らす設定では、揺れと閃光を出さない
  - 炎の矢：火の粉と煙を散らす火の玉。当たると爆発して炎が立ちのぼり、床に焦げ跡が少し残る
  - 氷の矢：冷気の尾を引いて回る氷のかけら。当たると床から氷の結晶が突き出し、砕けて破片が飛び散る
  - 光の槍：一瞬で走る光の柱。当たると天から光が降り、十字のきらめきと強い閃光
  - 闇の矢：まわりを暗くする黒い玉。当たると床に渦が開いて閉じ、はじけて黒いもやが残る
  - 衝撃波は広がる光の輪とちり、なぎ払いは光の筋、癒し・再生は立ちのぼる光の粒
  - 相性：矢が弱点を突くと大きく派手に（二重の輪と白い閃光を足す）、効きにくいと小さくくすんだ色になる（CastEvent の affinity）
  - 当たったとき：敵が一瞬白く光り、当たった向きへのけぞる。与えたダメージの数字は、矢が当たった瞬間に出す。矢が飛んでいるあいだは次の行動を待たせ、矢で倒した敵は当たるまで消さない
- 自動プレイ（バランステスト）は呪文書を持っていかないので、魔法を入れてもバランステストの結果は変わらない。魔法を入れた準備のバランスは、まだ確かめていない

### 敵の状態の表示
敵の頭上にマークを出し、プレイヤーに気付いているかどうかを見えるようにする。色だけでなく記号の形でも区別する。

| 敵の状態 | マーク | 意味 |
|---|---|---|
| 気付いていない（うろついている） | 「…」 | 今攻撃すれば不意打ちになる |
| 気付いた瞬間 | 「！」（1ターンだけ強調して表示） | 追跡が始まった |
| 追跡中 | 小さな「！」 | 不意打ちはできない |
| 見失った | 「？」 | 数ターン探したあと、うろつきに戻る |

- 敵が気付いた・見失ったことは、記録欄には書かない（頭上の「！」「？」だけで見せる。2026-11-14 に、記録に書くのをやめた）。

### 敵の特性
敵の特性は **属性** と **体質** の2軸で表す。マップ上の動き方は特性に含めず、マップの実装時に決める。

- **属性**（攻撃の種類。防具の選択に関わる）
  - 単一属性：**炎**・**氷**・**無属性**
  - 複合属性：**光**（炎＋無属性）・**闇**（氷＋無属性）
  - 複合属性のダメージは半分ずつに分けて計算する（例：光の攻撃10＝炎5＋無属性5）。耐性はそれぞれの成分に別々に効く。
  - 相性：**炎と氷**、**光と闇** は互いに弱点。
- **体質**（守りの種類。武器の選択に関わる）：普通・柔らかい・硬い・霊体の4種類。
- **体質の傾向はダンジョン特性（属性）と結び付ける**。例：闇のダンジョンには霊体が多い、炎のダンジョンには硬い敵が多い。
- **毒**：状態異常として仕組みは残すが、当面はどの敵にも持たせない。

### 防具と属性の対応
◎＝大きく軽減、△＝半分の成分だけ軽減、×＝効果なし

| 防具 | 炎 | 氷 | 無属性 | 光 | 闇 |
|---|---|---|---|---|---|
| 耐火のマント | ◎ | × | × | △ | × |
| 耐氷のマント | × | ◎ | × | × | △ |
| 鎧 | × | × | ◎ | △ | △ |
| 光の専用防具 | | | | ◎ | |
| 闇の専用防具 | | | | | ◎ |

- 鎧は光と闇の両方に半分効くので、属性がわからないときの保険になる。保険が強すぎると情報を集める意味が薄れるので、鎧の軽減率は低めにする。
- 空欄の効果は未決。

### 武器と体質の対応
◎＝よく効く、○＝普通、△＝効きにくい、×＝ほぼ効かない

| 体質 | 例 | 剣（斬る） | 槌（叩く） | 杖（魔法） |
|---|---|---|---|---|
| 普通 | ゴブリン | ○ | ○ | ○ |
| 柔らかい | スライム・獣 | ◎ | ○ | △ |
| 硬い | 岩トカゲ・ゴーレム | △ | ◎ | ○ |
| 霊体 | 亡霊 | × | △ | ◎ |

### 武器への属性付与
- 武器に魔法をかけて、一時的に属性を付けられる。属性の弱点（炎↔氷、光↔闇）はこれで突く。
- 武器そのものは属性を持たない。武器は体質の軸、属性付与は属性の軸、と役割を分ける。
- **手段**：道具（消耗品）として使う。宝箱から手に入れ、ダンジョン内で使う。道具枠を使うので、食料・回復薬と取り合いになる。
  - 例：炎の砥石・氷の砥石・光の聖水・闇の香油
- **持続**：攻撃回数で数える（例：5回攻撃するまで）。歩いても減らない。
- **重ねがけ**：付けられる属性は1つだけ。新しく付けると上書きされる。
- **同じ属性の敵**：敵の属性と同じ属性で攻撃すると、効きが半分になる。

### ダンジョン特性
- 隠れているダンジョン特性は、5つの属性のうち1つ。
- その属性の敵を中心に、成分の属性の敵も混ざって出る（例：光のダンジョンなら光の敵が中心で、炎と無属性の敵も出る）。

### 装備枠
- 武器：1つ
- 防具：1つ
- 道具：複数（数は未決）

### 空腹（探索のコスト）
- プレイヤーは満腹度を持ち、行動するたびに減る。
- 満腹度は食料で回復する。食料は宝箱や敵の落とし物で手に入る。
- 満腹度が0のときは、行動するたびにHPが減る。

### 階の広さと満腹度（以前の「成長（ランク）」）
ランクと強化は、2026-11-14 になくした。踏破の経験もない。以前は、準備フェーズ（今はない）で経験と金貨を払ってランク（1〜9）を上げると、広さ・満腹度・報酬が増えていた。
- 広さと満腹度は、ダンジョンごとに管理画面で決める（広さや階の数からは計算しない）。
- 難しさの段階は、広さや満腹度を変えたダンジョンを増やして表す（管理画面で複製して作る。プレイヤーは挑戦のたびに選ぶ）。広さは100×100が上限。
- 実装は `src/game/floorParams.ts`。

| 項目 | 決め方 | 標準のダンジョン |
|---|---|---|
| マップの広さ | ダンジョンの設定で決める | 80×80 |
| 満腹度（はじめの満腹度で、上限） | ダンジョンの設定で決める | 13132 |
| 敵の密度 | `ENEMY_CONFIG.density`（今は0.0075）×40÷広さ（広さに比例する程度に、敵の数を抑える） | |
| HPの自然回復 | min(20, 広さ÷2)ターンごとに1 | |
| 宝箱の金貨 | 深さ×5G | |
| ボスの報酬 | 50G | |

- 敵の密度・回復の式は、自動プレイで測った40×40を基準にしている。
- 満腹度の目安：満腹度を無制限にして自動プレイで測ると、踏破までのターン数（上位10%）は20×20で399、30×30で939、40×40で1571と、40×40まではほぼ広さ²だった（階が3つのとき）。40×40より広いと少し余分にかかる。歩く距離は階の数にも比例する。以前は、この目安から式で自動に決めていたが、管理画面で決めるように変えた。広さや階の数を変えるときは、満腹度も見直す。
- 敵の密度：密度が一定だと敵の数が面積に比例して増え、60×60では正しい準備でも道中の消耗でクリア率が45〜78%に落ちた。広さに比例する程度に抑えた。
- HPの自然回復：狭いマップは探索が短く、回復する時間が足りずにボス戦で負けやすかった（30×30で正しい準備が70〜88%）。広さに合わせて回復を速くした。
- 敵の強さは、広さでは変えない。

### セーブ
- 周回をまたいで残すのは、次が何回目の挑戦か・貯めた金貨・買った武器・防具・呪文書・道具の倉庫・前に選んだ持ち物（`src/game/save.ts`）。昔の記録にあったランク・経験・持ち越したカード・持ち帰った金貨（bonusGold）は、読み飛ばす。金貨・持ち物・倉庫のない昔の記録は、空から始める。
- ブラウザ（localStorage）に保存する。保存できない環境でも遊べる。
- 出発した時点で「次の挑戦」として先に保存する。探索の途中で再読み込みしても、同じ挑戦をやり直せない。

### 探索の中断と再開
- 探索の途中の状態は、周回の記録とは別に、1手ごとに保存する（`src/game/runSave.ts`）。ブラウザの「戻る」・再読み込み・スマホがページを閉じたときも、次に開けば同じ探索の続きから始まる。探索が終われば消す。
- 乱数の状態も一緒に保存するので、閉じて開き直しても、同じ行動をすれば同じ結果になる（やり直して良い結果を引くことはできない）。
- 階の形（マップ）は保存しない。シードから同じ形を作り直せるので、読み込むときに作り直す。作り直した形が保存したときと違えば（ゲームを更新してマップの作り方が変わったときなど）、続きはあきらめて新しい挑戦を始める。知らない敵や道具があるときも同じ。
- 探索が終わった時点で結果を周回の記録に書く（「結果を見る」を押す前に閉じても、結果は残る）。
- ブラウザの「戻る」は、探索中は一度受け止めて「ページを離れますか？」と確かめる。完全には防げない（iPhone の端からのスワイプ、戻るの連打、画面に一度も触れていないとき）ので、防ぐことより、離れても続きから遊べることを主にしている。

## 設計上の狙い
- **脇道に寄るかどうかの判断**：空腹で探索の量に上限があるので、全部の道は回れない。

## 今の進め方（2026-11-06）
- **準備フェーズはなくした**（2026-11-14。それまでは `SKIP_PREP` で飛ばしていた）。毎回、そのダンジョンに有利な装備（`data.ts` の `FAVORABLE_GEAR`）と回復薬2つ、そのダンジョンで有利に働く呪文書2冊（`bestLoadout.ts` の `favorableSpellbooks`。そのダンジョンのその属性の敵に与えるダメージが多い順。標準のダンジョンでは、炎：氷の矢と光の槍、氷：炎の矢と光の槍、光：闇の矢と氷の矢、闇：光の槍と炎の矢、無属性：どれも同じなので炎の矢と氷の矢）で、すぐダンジョンから始まる（`src/game/depart.ts`）。流れは「ダンジョンを選ぶ → ダンジョン → 結果 → 次のダンジョン」。準備のカード・店・持ち越し・所持金は、変更の履歴から戻せる。
- 通常の敵と強敵の HP・攻撃力を `data.ts` の値の半分にし（`ENEMY_CONFIG.strengthRate`。ボスはそのまま、防御力もそのまま）、通常の敵の数を1.5倍にした（密度 0.005 → 0.0075）。
- この変更で、無属性のダンジョンでは外れた準備（剣＋光の衣）でもクリア率が約80%になり、「準備で勝負が決まる」が崩れている。バランステストの上限（`WRONG_LIMIT.neutral`）は一時的に0.9に緩めた。敵の強さを見直すときに、あわせて見直す。
- 地図（以前の準備フェーズのカード。階段までの道筋が最初から見える）の仕組みは、準備フェーズをなくしたときに使い道がなくなったため、2026-11-14 に消した（探索の状態の `hasMap`・テスト・バランステストの「地図」も）。持っていく方法を作るときは、作り直す。参考：視界を壁にさえぎられないようにした時点で、地図で減るターン数は約28%だった（地図なし約190ターン、地図あり約138ターン）。
- ランクと強化、踏破の経験をなくした（2026-11-14）。広さ・満腹度は、ダンジョンごとに1つずつ決める（標準のダンジョンは、以前のランク1の値。広さ80×80・満腹度13132）。報酬は一定（宝箱の金貨は深さ×5G、ボスは50G）。ランクごとのバランステスト（ランク2〜5）はなくした。
- 上の階に戻れる。2階目からは降りてきた入口が上り階段で、踏むと1つ上の階の下り階段の上に戻る。一度離れた階は、敵（倒した敵はいないまま。残りはうろつきに戻る）・宝箱・晴れた霧を覚えている（`ExploreState.visited`）。1階目の入口はダンジョンの外への出口なので上れない。

## スマホでの操作（実装は `src/ui/ExploreScreen.tsx`）
- 幅48rem以下では、探索画面を画面の高さぴったりの1画面に収め、スクロールしなくてもすべての操作に届くようにする。上から、階の名前と「装備と敵」ボタン → 3D画面（画面の端まで広げ、残りの高さをすべて使う） → HP・満腹度 → 道具（1行。多ければ横にスクロール）。
- 装備・見えている敵・記録は1画面に収まらないので、「装備と敵」ボタンで画面全体に重ねて開く。いちばん新しい記録の1行は、3D画面の上に重ねて出す。
- この階の地図（ミニマップ）は、PCでもスマホでも3D画面の右上に小さく半透明で重ねる（3D画面の幅の20〜24%、最大7rem）。背景は塗らずに透かし、指やクリックは下の3D画面へ通す。広いマップほど縮めて表示されるので、主人公と階段の印はマップの広さに合わせて大きくする。
- 3D画面は残りの高さを使うので、その下に出たり消えたりするものを置くと、3D画面が伸び縮みして画面全体が揺れる。「壁があって進めない」などの知らせは3D画面の上に重ね、道具の行は道具がなくなっても同じ高さにしている。
- 移動は3D画面の上で行う（十字キーはなくした。決まった位置のボタンを見ずに狙うのが難しく、操作性がいまいちだったため）。キーボードの矢印キー・WASD・スペース（待つ）はそのまま使える。
  - **タップ**：そのマスまで、一度見た道を通って歩く。道筋を床に点で示す。敵をタップすると、その敵を追いかけて攻撃する（1回攻撃したら止まる）。歩いている途中にもう一度タップすると止まる。敵が見えても立ち止まらない（2026-11-14 に、立ち止まるのをやめた）。
  - **なぞる（仮想スティック）**：3D画面のどこでも、指を置いて12px以上ずらすと、指を置いた場所にスティックが出て、ずらした向きに歩き続ける。指を戻す（半径56pxの25%以内）と止まり、離すと消える。12px未満で離したときはタップとして扱う。向きの計算は `src/ui/stick.ts`。
    - 斜めに倒したとき（斜め45度の線から±22.5度以内。たとえば右上なら右から22.5〜67.5度）は、上下と左右の2つを候補にし、1歩ごとに、指の向きに近い方へ進む。近い方が壁なら、もう一方へ進む。ちょうど45度なら上下を先にする。両方とも壁なら止まる。たとえば右寄りの右上に倒したまま、右が壁の通路では上へ、上が壁の通路では右へ進み、壁に沿って自動で曲がっていく。斜めの範囲の外では、近い方の1方向にだけ進む。
  - **歩く速さ**：1マス385ms（1秒に約2.6マス。2026-11-14 に、270ms から速さを3割落とした）。なぞり続けたとき、タップで歩くとき、キーを押し続けたときで共通。
  - **道具のボタン**：アイコンの横（スマホでは下）に、道具の名前を小さい字で出す。
  - **振動**：敵に攻撃を当てたとき（呪文の矢は当たった瞬間）と、攻撃を受けたときに、スマホを短く震わせる。踏破したとき・力尽きたときは長く震わせる（`src/ui/haptics.ts`）。振動の仕組み（`navigator.vibrate`）がある Android の Chrome などだけで震え、iPhone の Safari には仕組みがないので震えない。
  - **待機のボタン**：3D画面の右下の「待機」で、その場で1ターン待つ（スペースキーと同じ）。スマホでは、下に重ねて出す記録の行より上に置く。
  - **体力・満腹度・魔力**：数字を出さず、ゲージだけで見せる（読み上げには割合を伝える）。体力と満腹度は、残りが4分の1を切るとゲージが点滅する。体力と魔力は、増えた・減った瞬間にゲージが光り、魔力が足りずに唱えられないとゲージが震える。経験値は数字も出す。
  - **主人公をダブルタップ**（0.35秒以内に2回）：その場で1ターン待つ。1回だけのタップでは待たない（うっかり触れてターンが進まないように）。3Dでは主人公の絵が足元のマスより上に伸びているので、絵そのものに当たったかで判定する。
  - **階段**：踏むとそのまま次の階へ降りる・上の階へ戻る（「階段を降りる」ボタンはなくした）。踏む動きを見せてから降りるよう、踏んだ次の行動として降りる。タップで歩くときは、思わぬところで降りないよう、下り・上りの階段が行き先でなければ階段のマスを避けて歩く（階段を通らないと届かないときだけ通る。`walkPath` の avoid）。
- 画面の大きさによらず、主人公のいるあたりの1マスが画面上で約48px（CSSピクセル）に映るよう、カメラの視野の広さを決める。スマホの縦画面（幅約390px）で横に約8マス、PCの探索画面（幅約670px）で横に約14マス映る。

## 3D表示（実装は `src/ui/explore3d.ts`）
- Three.js（WebGL）で、斜め上（約63度）から見下ろす。カメラの角度は固定で、主人公を滑らかに追う。1マスが画面上で約48pxに映る（上の「スマホでの操作」を参照）。
- 床は板、壁は箱。壁は上面を明るく、側面を暗くして立体感を出す。
- 壁の高さはマスと同じ（1倍）。通路が深く見えるよう、0.6倍から上げた。敵・宝箱・階段のすぐ手前（カメラ側）に壁があっても、壁は透かさない（前は半透明にしていたが、やめた）。
- 床・壁の上面・壁の側面には、ダンジョン特性ごとのテクスチャを貼る（なめらかな質感。仕様は [textures.md](textures.md)。氷と炎は画像から作った素材、ほかは仮の素材）。読み込めなかったときは特性ごとの色で描く。
- 壁は角張った箱にせず、自然な岩のように描く：床に面した上の縁と、出っ張った縦の角を丸め（半径0.16マス）、表面を少し波打たせる（最大0.045マス、ダンジョンの中の位置で決まるので、となり合う壁はつながったまま）。壁どうしが接する面は描かないので、上面にマスの継ぎ目の線が出ない（src/ui/softWall.ts）
- 床と壁はフォンシェーディングで描き、たいまつの光でツヤを出す。ツヤの強さはダンジョン特性ごとに変える：氷は強く（鋭く小さな照り返し）、光は中くらい、炎は弱く、無属性と闇はツヤなし。
- 壁の根元に影（接地影）を付ける。壁に接する床の辺に、壁側ほど暗い帯（幅はマスの0.4倍、壁際で80%の暗さ）を敷く。まだ見ていない壁には付けない（霧の向こうの形がわからないように）。
- 主人公は立体の模型（`src/ui/hero3d.ts`）。ドット絵と同じ色の、フード付きのマント・顔・長めの髪・服とベルト・袖と手・靴で組み立て、装備した武器（剣・槌・杖、`src/ui/weapon3d.ts`）を左手に持つ。フォンシェーディングで陰影をなめらかにし、うっすらツヤを出す（武器の金属と宝石は強く光る）。マントとフードは装備した防具の色に変わる。歩いた向きへ体を回し、歩くあいだは少し上下に揺れる（動きを減らす設定では揺らさない）。主人公をタップしたかは、体より少し大きい見えない箱で判定する。
- 敵を攻撃すると、主人公が敵の方を向いて武器を振る（約0.36秒）。振りかぶってから約0.1秒で振り下ろし切り、少し止めてから構えに戻る。剣は肩の上から斜めに斬り下ろし、槌は頭の上から真下へたたきつけ、杖は少し引いてから先を敵へ突き出す。武器なしはこぶしを突き出す。体も少し前へ傾けて踏み込む（動きを減らす設定では振らない）。同時に武器ごとの攻撃の音を鳴らす（[sounds.md](sounds.md)）
- 敵は、形も色もプログラムで組んだ立体の模型で描く（`docs/textures.md`）。歩いた向きへ体を回し、歩く・浮かぶ・弾むなど、体つきに合わせて動く。模型のない敵（管理画面で足した敵など）は、ドット絵を常にカメラを向く板（ビルボード）として立てる。見えなくなった敵の模型は隠すだけで、倒されるか階を移るまで片付けない（また見えたときに組み立て直すと、動きが引っかかるため）。
- 階段は立体の模型（`src/ui/stairs3d.ts`）で、ダンジョンの特性ごとに石の色と飾りを変える。
  - 下り階段：床をくり抜いた四角い穴の中へ、奥へ下りていく石段。下の段ほど暗く、下り切った奥の壁に、さらに下へ続く通路の口が開いている。穴の縁は床より少し高い石の枠
  - 上り階段：両脇に斜めの石の壁がある、奥へ上っていく石段。上り切った先に、柱と梁で囲んだ暗い入口がある
  - 無属性：すり減った灰茶色の石（段の高さと幅が少し不ぞろい）。炎：黒い玄武岩で、段の角に溶岩の割れ目が光り、通路の奥が赤く光る。氷：青白い氷で、段の角に霜、穴の縁と入口からつららが下がる。光：白い大理石に金の縁取りで、奥から暖かい光。闇：黒紫の石で、縁にとげのような岩が並び、奥から紫の光がかすかに漏れる
- 宝箱は開けたあとも消さず、ふたを後ろへ倒して開いた形でその場に残す（空の宝箱に乗っても何も起きない。持ち物がいっぱいで道具を残したときも、開いた形にする）。
- 宝箱は、箱の本体とかまぼこ形のふたでできた立体で、宝箱の写真から作ったテクスチャ（錠前・鉄の帯・取っ手）を貼る（[textures.md](textures.md)）。
- 霧：まだ見ていないマスは描かない。一度見たマスは暗く（明るさ0.3）、今見えているマスは明るく描く。
- 光と影：見える範囲の明るさは、ほぼ主人公のたいまつの光で決まる。環境光（0.3）と上からの光（0.25）は弱くして、光の届かない場所はかろうじて形がわかる暗さにしている。
  - たいまつは主人公の手元の高さ（0.85。壁の上面1より低い）、少し手前（カメラ側に0.3）に掲げた点光源で、強さ10・届く距離9マス。光の色は暖かいオレンジ色。ただし氷のダンジョンだけは青白い光にする（暖かい光は氷の青を打ち消して、黄色っぽい灰色に見せてしまうため）。
  - たいまつの光は壁にさえぎられて影ができる（シャドウマップ、縁を少しぼかす）。入口から部屋をのぞくと光がくさび形に差し込み、曲がり角の先や部屋の奥は暗いまま。
  - 影の地図は6方向から描くので重い。たいまつが動いたときと、壁の並びが入れ替わったときだけ描き直す。`?shadow=off` を付けると影を切って比べられる。
- 描く解像度は、画面の1ピクセルあたり2ピクセルまで。描くのが間に合わないコマが続く端末では、滑らかに動く方を優先して1.5ピクセルに下げる（`src/ui/explore3d.ts` の `RESOLUTION`。一度下げたら、その画面を開いているあいだは戻さない）。
  - 雰囲気を優先して、ダンジョンの中の物はすべてたいまつの光を受ける：床・壁・主人公・敵・宝箱・上りと下りの階段・強敵やボスの足元の輪。暗がりにいる敵は暗く、壁の影に入れば影の中に沈む。
  - 敵のドット絵は、カメラの方を向けた板に照らされる素材で描く。板の面の向き（法線）は真上にしてあり、光の当たり方は足元の床と同じになる（カメラの方へ向けたままだと、主人公とカメラのあいだにいる敵が背中から光を受けて真っ暗になるため）。
  - 画面の上に重ねる目印（敵の頭上の「…／！／？」とHPの棒、ダメージの数字、歩く道筋の点、行き先の印）は、情報なので光の影響を受けない。
  - 霧の明るさはマス単位ではなく、ピクセル単位で決める（`src/ui/explore3dKit.ts` の `createFog`・`applyFog`）。マスごとの「今見えている」「一度見た」を1マス1ドットの小さな画像（霧の地図）に書き、描くときにそれをなめらかに引き伸ばして読む。そのため、見えている場所・一度見ただけの場所・まだ見ていない場所の境目は、マスの形の段ではなく、1マスほどのなだらかなグラデーションになる。ゲームのルール（どのマスが見えているか、敵に気付けるか）は今までどおりマス単位。
  - 見えている場所は、主人公（歩いている途中の位置）からの距離で、ピクセルごとになめらかに暗くする（そばで1、視界の端で0.5。smoothstep）。一度見ただけの場所は0.3。まだ見ていない場所は描かず、その手前で背景の色に溶け込ませる（探索した範囲の外周がカクカクしない）。
  - 霧の地図の値はパッと切り替えず、目標へ少しずつ近づける（1秒あたり9の速さ）。初めて見えた場所は、背景から浮かび上がるように現れる。階を移ったときと、動きを減らす設定ではすぐ切り替える。
  - 床・壁・敵・宝箱・階段・強敵の足元の輪・壁の根元の影の帯に、同じ霧をかける（影の帯は黒の半透明なので、色ではなく濃さを消す）。主人公と、画面に重ねる目印には霧をかけない。
- 画面効果：自分が攻撃したときはカメラが少し寄って戻り（5%、180ms）、敵に攻撃されたときは寄ったあと少し引いて戻る（8%、260ms）。動きを減らす設定では行わない。
- 戦闘中のズーム：追ってきた敵が主人公の隣（上下左右）にいるあいだと、攻撃が起きてから0.9秒のあいだは、主人公を中心に画面を1.35倍に寄せる（約0.4秒でなめらかに寄り、戦闘が終わると約0.75秒で戻る）。攻撃のときの寄って戻る効果は、この上に重ねる。動きを減らす設定では、なめらかにせずすぐ切り替える。
- 効果音：1歩進むたびに、ダンジョンの特性に合わせた足音を鳴らす（無属性は土を踏む低く重い音、炎は焼けて尖った石の先端が砕けるゴリッという音、氷は雪を踏むシャリ・ジャリという音を氷の洞窟に響かせ、光は磨かれた石の神殿、闇は硬い石の洞窟）。宝箱から金貨か道具を取ったときは、宝箱が開く音（木の宝箱が「ぎー」ときしみながら開き、「ガコッ」と止まる音）を鳴らす。ダンジョンにいるあいだは、特性ごとの環境音を流す（無属性は洞窟を吹き抜ける風のうなり、炎は溶岩の地鳴り・泡・火のはぜる音、氷は氷の洞窟の細い風・氷のきしみ・水滴、光は神殿の広間の合唱のような和音と鐘、闇は洞窟の奥の不気味なうなり・ささやき・うめき声）。探索画面の上のボタンで、音のオン・オフと、効果音・環境音それぞれの音量を変えられる（`docs/sounds.md`）。
- ダメージの数字：与えたダメージ（生成りの色）は敵の、受けたダメージ（赤）は主人公の頭の上に出す。小さく出て、なめらかに大きくなりながら少し浮かび（0.6→1.3マス、0.35マス上へ）、後半でなめらかに透けて消える（0.25秒）。同じマスに続けて出るときは横にずらす。ゲームのルールは、行動ごとに入ったダメージを `ExploreState.hits` に記録するだけで、画面はそれを読んで数字と画面効果を出す。
- 壁にぶつかったときの「壁があって進めない」は画面に出さない（なぞって歩くと何度もぶつかるため）。
- スマホのブラウザのタップの強調表示（指が触れているあいだ重なる半透明の色）は、3D画面では消している（`-webkit-tap-highlight-color: transparent`）。暗い画面の上では、タップするたびに白く光ったように見えるため。指の形のカーソルも、マウスで操作するときだけ出す。
- 床と壁は、主人公の周りの画面に映る範囲（横27×縦23マス）だけを描く。マップの広さに関係なく軽い（ヘッドレスのChromeのソフトウェア描画で、100×100でも約60fps）。
- タップ・クリックは、カメラから床へ向けた線が当たった点からマスを求める。
- WebGL2 が使えない環境や、3D表示を作れなかったときは、遊べないことを画面に出す（以前の2D表示は、2026-11-14 になくした）。

## 探索画面の表示と操作（実装は `src/ui/ExploreScreen.tsx`。1コマの情報とミニマップは `src/ui/exploreRender.ts`）
- 主人公を常に画面の中央に置き、1歩ごとに前の位置から新しい位置へ滑らかにスクロールする（1マス120ms）。敵も同じように滑らかに動く。
- ダッシュはなし。キー（矢印キー・WASD）や画面の方向ボタンを押し続けると、1マスずつ歩き続ける。歩く速さはOSのキーリピートに左右されない。
- 動いている途中に押した操作は2つまで覚えておき、順に行う。
- マップのマスをタップ・クリックすると、一度見た通路を通ってそこまで歩く。道の途中に敵がいれば手前で止まる（勝手に攻撃しない）。敵そのものを選んだときだけ、隣に着いたら1回攻撃して止まる。キーを押すか別の場所を選ぶと止まる。
- 斜め移動はなし。
- 動きを減らす設定（prefers-reduced-motion）のときは、滑らかな動きをせずに切り替える。
- 床と壁は、ダンジョン特性ごとのテクスチャで描く。素材の仕様は [textures.md](textures.md)。
- ダンジョンに入った瞬間に、見た目で特性がわかってよい（勝負どころは出発前の準備なので、攻略のし甲斐は減らない）。将来ダンジョンの中で特性を知らないと悩む判断（撤退など）を足すときは見直す。

## ボス階
- 最後の階（今の設定では3階）の階段を降りるとボス階（最深部）に出る。ボスを倒せば踏破。
- 入口からの短い通路と、大部屋が1つだけの決まった形（`generateBossFloor`）。宝箱はない。霧はある。
- 大部屋には、ボスといっしょに雑魚敵がたくさんいる（その属性の道中の敵から選ぶ。ボスのそばと入口の近くは避ける。数はダンジョンの設定の「ボスの部屋の雑魚敵の数」`enemies.bossMinions`。標準は10体）。ボスを倒せば、雑魚敵が残っていても踏破。
- ボスは歩く：気付くまでは大部屋の中をうろつき、気付いたら追ってくる（強敵は動かないが、ボスは動く）。離れようとすると必ず背後から攻撃してくる。

## 出発の準備（店。2026-11-14。ルールは `src/game/shop.ts`、画面は `src/ui/ShopScreen.tsx`）
- 流れは「ダンジョンを選ぶ → 情報屋 → 出発の準備（店）→ ダンジョン → 結果」。ダンジョンの属性は情報屋に入る前に決まるが、画面には出さない。店の画面には、情報屋から聞いたことだけをメモとして出す（おすすめの印は付けない）。
- 金貨は最初は0。ダンジョンで持ち帰った金貨（力尽きた・リタイアしたときは半分）が貯まり、店で使う。足りなくなっても補わない。
- 何も持たずに始まる。持ち物は、すべて店で買う（以前の、出発時に有利な装備・回復薬・呪文書を自動で持たせる仕組みはやめた）。
- 武器・防具・呪文書は、一度買えばずっと使える。出発のたびに、武器1つ・防具1つ・呪文書3冊までを選ぶ。
- 道具（回復薬・食料・砥石など）は倉庫に入り、出発のたびに8つまで持っていく数を選ぶ。使わずに残った道具（ダンジョンで拾ったものも）は、踏破・力尽きた・リタイアのどれでも持ち帰って倉庫に戻る。
- 武器と防具は種類ごとに10段階。上の段階ほど高く、強い（武器：攻撃力、防具：守り＝受けるダメージから引く数と、効く属性のダメージの割合）。1段目は以前と同じ強さ。
- 店に並ぶのは、店に入ったときに持っていたいちばん上の段階の2つ上まで（持っていなければ2段目まで）。下の段階は、持っていても並べない。店で上の段階を買っても、並びはその場では広がらず、次に潜るときの店で広がる（2026-11-14 に変えた。以前は買うとすぐ広がった）。
- 買ったものは返品できない。持っていくものの欄で押すと、外すだけ（買ったものはなくならない）。スマホでは、持っていくものの欄をたためる。
- 品物の欄は、1つを1段に収める（値段とボタンを名前の右に置き、説明は1行に切る。品物を押すと全文）。スマホで品物が多く見えるように。
- 品物の名前・値段と、武器・防具の段階ごとの性能は、品物の設定ファイル `src/game/items.json`（管理画面の「品物」タブ。`src/game/itemMaster.ts`）にある。武器と体質の相性・防具の効く属性・道具の働きは、プログラムで決まっていて変えられない。上の段階より安い・弱い段は、公開できない。

## 情報屋（2026-11-14。ルールは `src/game/informant.ts`、画面は `src/ui/InformantScreen.tsx`）
- ダンジョンを選んだあと、店の前に、これから入るダンジョンのことを情報屋から聞き出す。
- 聞けることは3つ：ダンジョンの属性、多い魔物の体（いちばん多い体質。ダンジョンの設定の encounters から数える）、奥のボス（名前・属性・体）。
- 1回の訪問で聞けるのは2回まで（`INFORMANT_CONFIG.questions`）。同じことは2度聞けない。
- 1回目だけ「それとなく聞く」ができ、無料。答えはぼんやりしていて、本当の答えと違う答えの2つが混ざる（例：属性なら、2つの属性の様子を言う）。違う答えはダンジョンのシードから決まるので、同じダンジョンなら同じ答え。
- 「はっきり聞く」は情報料を払い、正しい答えが聞ける。情報料は、属性30G・多い魔物の体20G・ボス20G（品物の設定 `items.json` の information。管理画面の「品物」タブの「情報料」）。
- 値段の目安（自動プレイ200回、1階・20×20マス）：何も持たないと1回で約16G、合わない1段目の装備では約22G、合う1段目の装備では約124G持ち帰る（踏破97%）。属性の情報料は、合う装備で増える持ち帰りの約3割。序盤は無料の手がかりで推理し、稼げるようになったら情報を買う、という流れを狙う。
- 払った情報料は、すぐ保存する。聞いたことは、店の画面の上にメモとして残る（うわさは「（うわさ）」と付く）。
- はっきり聞いたこと（うわさは使わない）があれば、店でそれに合う品物に「おすすめ」の印を付ける（`shop.ts` の recommended。2026-11-14）。
  - 属性（ダンジョン・ボス）がわかれば：その属性の攻撃をいちばん減らす防具の種類（すべての段階）、その属性によく効く砥石・聖水・香油と、属性の矢の呪文書。
  - 体（多い魔物・ボス）がわかれば：その体によく効く武器の種類（すべての段階）。普通の体なら、武器には付けない。

## 生成アルゴリズム
実装は `src/game/map.ts`。開発サーバーで `?view=map` を開くと、生成結果を確認できる。

1. 小部屋をランダムに配置する（多さと大きさは生成の設定にある。今は一辺3〜9マス）。
2. 残りの空間を穴掘り法（再帰的バックトラック）の迷路で埋める。
3. 部屋と通路を隔てる壁に穴を開けて全体をつなぐ。つながったあとも、一部の壁は壊してループを作る。
4. 入口から最も遠い通路までの距離の55〜80%の位置に、階段を置く。そこまでの最短路を本道とする。
5. 本道から外れた行き止まりに、宝箱か強敵を置く。宝箱の金貨は本道から遠いほど多い（強敵の強さへの反映は未実装）。

### ダンジョンの設定ファイル（`src/game/dungeons/<ID>.json`、管理画面 `?view=admin`）
ダンジョンの設定は、ファイル1つがプレイヤーの選べるダンジョン1つになっている（標準のダンジョンは `standard.json`）。プレイヤーは、挑戦を始めるたびにダンジョンを選ぶ。
ファイルには、名前と説明、マップと探索の設定（下の項目）、ダンジョンの属性ごとに出る敵（`encounters`。敵は `enemies.json` のマスターから選ぶ）が入っている。詳しくは `docs/enemy-master.md`。

管理画面は、敵のマスターデータ（`enemies.json`）とダンジョンの設定を1つの画面にまとめていて、種類ごとの8つのタブに分かれている（敵／名前と説明／ダンジョンに出る敵／階の数・広さ・満腹度／小部屋／敵の数と置き方／レベルと強敵の報酬／魔法。`?view=admin&tab=magic&dungeon=deep_cave` のように、タブと直すダンジョンを指して開ける。値を変えたタブには点が付く）。「敵」のほかは、選んだダンジョンの設定。ダンジョンは、複製して作る・消すこともできる。「階の数・広さ・満腹度」から「魔法」までの5つのタブでは、値を変えると、その値で作ったマップの見本（敵の位置つき）をすぐに見られる。「変更を公開」で本番に反映される（敵のデータといっしょに、変えたファイルをまとめて1回のコミットで保存する。`docs/enemy-master.md`）。ボスの階は形が決まっているので変わらない。

- 階の数・広さ・満腹度：通常の階の数（1〜10。その下にボスの階）と、階の広さ（一辺20〜100マス）。満腹度（探索のはじめの満腹度で、上限。100〜100000の整数）は、設定した値をそのまま使う。広さや階の数を変えても自動では変わらないので、いっしょに見直す。敵の数・HPの回復の速さは、広さから自動で決まる（`src/game/floorParams.ts`）
- 小部屋：部屋の多さ（迷路のセル数に対する、部屋を置こうとする回数の割合。今は0.04）、部屋の一辺の最小と最大（奇数）。部屋を増やすと迷路の通路が減り、行き止まりに置く宝箱と強敵も少し減る
- 敵の数の倍率：通常の敵の数を何倍にするか（1が今の数。広さに合わせて増える分はそのまま）。強敵とボスは変わらない
- 敵を置く場所：部屋にも通路にも／部屋だけ／通路だけ。部屋にも通路にもでは、部屋の床が通路の床の何倍選ばれやすいか（部屋の選ばれやすさ）で偏らせる（0なら部屋に置かない）。どこも同じなら、前と同じ配置になる
- 群れ部屋：部屋ごとに確率で、敵がまとまっている部屋にして、通常の敵とは別に決めた数だけ置く。通路だけのときは作らない
- 部屋の敵は部屋から出ない：部屋に置いた敵は、主人公に気付くまで部屋の中だけを歩く
- レベルと強敵の報酬：最初のレベルアップに要る経験値、1レベルごとに増える必要経験値、1レベルで増える最大HPと攻撃、レベルの上限、強敵の金貨と経験値の倍率。画面にレベルごとの必要経験値の合計と、能力の増え方の表が出る。強くしすぎると、外れた準備でもクリアできてしまう

## テストと管理画面の設定
管理画面で品物・敵・ダンジョンの設定を変えて公開しても、自動チェック（`npm test`）が落ちないように、テストを3つに分けている。
- ふつうのテスト：ルールどおりに動くか（値段の分だけ金貨が減る、満腹度が0で力尽きる、など）を確かめる。ゲームが読む設定ファイルは、テスト用の決まった中身（`src/game/testdata/`）に差し替えて動く（`vite.config.ts` の `testData`）。値段や強さを変えても、結果は変わらない
- 公開する設定ファイルのテスト（`src/game/publishedData.test.ts`）：本物の設定ファイルが正しい形か、管理画面で書き出した形のままかだけを確かめる。管理画面は正しくない設定を公開させないので、ふつうは落ちない
- バランスのテスト（`npm run test:balance`）：本物の設定で自動プレイし、遊びやすさを確かめる。自動チェックには入れていない
テスト用の設定（`testdata/`）は、ゲームのルールを変えて設定ファイルの形が変わったときだけ、合わせて直す。

## バランスの基準（`src/game/balance.test.ts`）
自動プレイAI（`src/game/autoplay.ts`）に、標準のダンジョンの各属性を40回ずつ遊ばせ、次を満たすように数値を調整する。
バランスのテストは時間がかかるので、今はふつうのテスト（`npm test`）と自動チェックから外している（ダンジョンの設定を自由に試せるように）。確かめるときは `npm run test:balance` で動かす。
本道だけを歩けば満腹度が0にならずに最深部まで着けるかも、ここで確かめる。
AIはプレイヤーと同じ情報（霧が晴れた場所と、見えている敵）だけで動き、まだ見ていない場所へ近づきながら階段を探す。

| 準備 | 基準 |
|---|---|
| 正しい準備（属性に効く防具＋体質に効く武器＋回復薬2つ） | クリア率80%以上 |
| 外れた準備（効かない防具と武器＋回復薬2つ） | 20%未満（無属性のダンジョンだけ40%未満） |
| 何も準備しない | 20%未満 |

- 無属性のダンジョンは「どの武器でも戦える」「鎧は保険なので効きが弱い」設計なので、外れても差が小さい。そのため基準を緩めている。
- 踏破はボスを倒すことまで含む。光のダンジョンは、正しい準備のクリア率が最も低い。
- 霧の中で階段を探すと1階あたり250〜400歩かかる。満腹度の上限600では空腹で力尽きる挑戦がほとんどになり、装備の差が出なかったので1600にした。
- 調整した値（40×40のとき）：満腹度の上限1600、HPの自然回復を20ターンごとに1、敵の攻撃力を当初の1.6倍。
- 調整後の結果：正しい準備で負けるときの死因は空腹、外れた準備で負けるときの死因は敵になっている。

## 守るべき条件（テストで確認する）

- 階段は入口からほどよく遠い位置にある（最も遠い通路までの距離の55〜80%）。
- 同じシードなら同じマップになる。
- 本道だけを歩けば、満腹度が0にならずに階段まで着ける。
- 脇道には宝箱か強敵が置かれる。

- 敵のデータ（強さ・属性・体質・ボス・見た目、ダンジョンごとに出る敵）は `src/game/enemies.json` にあり、開発用の管理画面（`?view=admin` の「敵」「ダンジョンに出る敵」タブ）から変えて公開できる。敵を足す・消すこともできる（`docs/enemy-master.md`）。
