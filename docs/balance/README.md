# バランスの記録

敵や主人公の強さを変えたとき、クリア率がどう動いたかを、数字で残す仕組み（2026-11-28）。

- 表と移り変わり：[report.md](./report.md)
- 最新のグラフ：[clear-rate.svg](./clear-rate.svg)
- 履歴（機械が読む形）：[history.json](./history.json)

## 何を測っているか
自動プレイ（`src/game/autoplay.ts`。画面で人が遊ぶのと同じ `step()` を、簡易のAIが呼ぶ）で、ダンジョンごと・属性ごとにクリア率を測る。

| 条件 | 中身 |
|---|---|
| 装備 | その属性に効く「正しい準備」（`balance.fixtures.ts` の `PREPS.right`）＋回復薬と食料（`SUPPLIES`） |
| 回数 | 属性ごとに、既定80回（同じシードの並びなので、同じデータなら同じ結果） |
| 属性 | 炎・氷・無・光・闇の5つ。表には、属性ごとと、その平均を出す |
| 目標 | 平均で60%前後（◎：±10ポイント以内、○：±20ポイント以内） |

注意：
- AIは、残響・共鳴や、情報屋の話を使わない。人が上手に遊べば、これより高くなる
- クリア率は、敵の強さを少し変えるだけで大きく動く（2026-11-28 の調整では、敵を0.4倍にすると42〜53%、0.38倍にすると69〜72%、0.5倍にすると13%以下だった）。微調整のときは、回数を増やして測る（`BALANCE_TRIALS=200`）
- 属性ごとのばらつき（同じダンジョンでも、闇だけ25%など）は、平均では見えない。グラフと表の属性別の列を見る

## 測り直す（再実行）
```sh
BALANCE_LABEL="何を変えたか" npm run balance:report
```
`docs/balance/` の history.json・report.md・clear-rate.svg が更新される。時間がかかる（ダンジョン1つにつき数十秒〜数分）。

| 環境変数 | 意味 | 既定 |
|---|---|---|
| `BALANCE_LABEL` | 何を変えたあとか（必須。表の「変えたこと」の列に出る） | － |
| `BALANCE_TRIALS` | 属性ごとの回数 | 80 |
| `BALANCE_DUNGEONS` | 測るダンジョンの ID（カンマ区切り） | すべて |
| `BALANCE_DATE` | 記録の日付 | きょう |
| `BALANCE_DRY` | 1にすると、ファイルを書かずに表だけ出す | － |

同じ日・同じ「変えたこと」で測り直すと、その記録を置きかえる。別の名前なら、履歴に足される。

## ファイル
- `src/game/balanceReport.ts`：測る・履歴を整える・表とグラフを作る（純粋な関数。テストは `balanceReport.test.ts`）
- `scripts/balance-report.ts`：ファイルを読み書きして、上を呼ぶ
- `src/game/balance.test.ts`（`npm run test:balance`）は、別の目的のテスト：「正しい準備なら勝てる／外れた準備なら負ける」という設計の確かめ。今回の「60%」の記録とは基準がちがう
